@bci-av/core

Holds the whole vocabulary and is the only package with no peer dependencies.

The shape of a symbol

Section titled “The shape of a symbol”
Field
bciAv BCI-AV number. Stable across editions — use it for persisted references.
id Slug from the primary gloss. Unique, but follows the gloss, so it can change.
gloss Primary English gloss.
synonyms Every English gloss, primary first.
names Gloss by ISO 639-1 code, as BCI writes it — see the warning below.
derivation How BCI composes the symbol. Present for 6,550 of 6,551.
pos Part of speech, as a colour. Bliss encodes grammatical class by colour.
svg Inline SVG with a viewBox and no physical dimensions.

Importing one symbol

Section titled “Importing one symbol”

symbols is a single array, so a bundler cannot split it: importing anything from the package root pulls all 6,551 symbols. Measured with esbuild, a consumer who wanted one symbol bundled 6.2 MB (1.4 MB gzipped).

If you need a known set rather than search, import them directly:

bundled
one symbol via the subpath ~1 KB
five symbols ~5 KB
the root entry 6.2 MB

The module name is the symbol’s id, and it exports the same BlissSymbol object the registry holds — as both a default and a named blissSymbol export.

Which should you use?

The root entry still carries the whole registry, because search and the gallery need every symbol and there is no way around that. Use it when you are searching; import directly when you already know which symbols you want.

Lookups

Section titled “Lookups”

getSymbolsByGloss is an exact synonym match, not a search: "housekeeping" and "housework" both resolve to the same symbol, while "house" resolves to its own.

Use getName, not names[lang]

names keeps BCI’s text verbatim, which means every synonym in that language as one comma-separated string — "hushållsarbete, hemarbete". It is also absent entirely for symbols BCI has not translated.

getName(symbol, lang) returns a single displayable name and falls back to English, then to the gloss.
